# End-to-end test, 2026-10-22

Penthera tested the way users and agents meet it: the npm package from a clean
`HOME`, the dashboard in a real browser, www.penthera.org, the skill, the
Claude Code plugin, the MCP server and AI mode. Nothing ran from the repo
checkout except the MCP server (PR #120, not merged yet) and AI mode (on main,
not in 1.8.1).

- **Package:** `penthera@1.8.1` from npm (`latest`), through `npx`
- **MCP server:** PR #120 at `033e064`
- **AI mode:** main at `74eea3f`
- **Machine:** macOS, Node 26.0.0, npm 12.0.1, Claude Code 2.1.195, Ollama running with no models
- **Isolation:** temp `HOME`, temp project folders, throwaway git repos. Nothing was published or pushed to main, and no npm state changed.
- **Production limits:** penthera.org got only the default and `quick` scans, at concurrency 3. No deep, fuzz or active modes.

## Summary

The core works: install, scans, deps, agents, the hook, reports, evidence
bundles, signed rule packs, the in-browser check and the MCP server's safety
model all behave as documented. Most commands answer in under 1.5 seconds,
and a URL scan takes about 10 seconds.

Four things would hurt a first-time user, and three of them are fixed in PRs:

1. **The Claude Code plugin does not load** (`conflicting manifests`). Fixed in #127.
2. **The dashboard's main flow dead-ends.** *Check my app*, then *Fix problems
   for me*, fails because the check wrote a report into the project. The rows are
   unreadable with real paths, and the run says "up to date" after finding a high.
   Fixed in #126.
3. **A scan of a Vercel site gets the scanner challenged, and the next scan
   reports the challenge page as the site** (five missing headers, no rate
   limiting). Fixed in #124. The cause, login POSTs plus an SQLi string in every
   URL scan including `quick` and the MCP `scan_url`, needs your decision (D1).
4. **The pre-commit hook points at the npx cache.** When the cache is cleaned it
   skips silently (exit 0). Needs your decision (D4).

## Starter and pro

**Starter** (no security background, follows the README): good up to the
second step. `npx penthera` explains itself, the in-browser check is fast and
honest about what it sends, and Simple mode words problems well. Before the
fixes, three things broke the path:
the plugin didn't load, *Check my app* → *Fix problems for me* dead-ended on
Penthera's own report, and the result rows were unreadable with real folder
paths. A starter scanning their own Vercel site would also get a false "missing
security headers" result on the second try. With #124, #126 and #127 the path
works end to end. The hook's silent skip (D4) is the remaining trap.

**Pro** (CI, SARIF, evidence, agents): solid. Exit codes are consistent,
JSON, SARIF and the audience reports are complete, evidence bundles and signed
packs catch tampering, and the MCP server's confinement and output limits are
careful. Gaps: SARIF results without a location (#125); test-fixture secrets
reported as HIGH, with no path-based demotion; `deps` saying "clean" when 117
of 145 packages weren't inspected; and a "passive" scan that is not passive to
a WAF (D1).

## Decisions for Daan

**D1. Login probes in every URL scan.** `probeAuthEndpoints` runs in `quick`,
`standard` and the MCP `scan_url`. It sends 9 credential POSTs and an
`' OR '1'='1` string to `/api/login`. The site's benchmark says "Standard run,
no attack payloads", and the MCP tool says "no attack payloads".
- (a) **Recommended:** move the SQLi smoke string and the 8-attempt rate-limit
  burst behind `--deep`, behind the active-scan gate (#95); keep one
  invalid-credential POST in standard. E10 would need a re-run, since the gain
  partly relies on these checks.
- (b) Keep them in `standard`, drop them from `quick` and the MCP `scan_url`.
- (c) Keep everything and change the wording to "no injection payloads except
  one login check".

**D2. penthera.org has no SPF or DMARC record.** It doesn't send mail.
- (a) **Recommended:** publish `v=spf1 -all` on `penthera.org` and
  `v=DMARC1; p=reject;` on `_dmarc.penthera.org`. A security tool's own domain
  should pass its own check.
- (b) Leave it, and accept the two MEDs on every scan of the site.

**D3. Vercel challenges the scanner after one default scan.**
- (a) **Recommended:** keep the firewall as is, ship #124 (an honest
  "challenged" result), and add one FAQ line: "Scanning your own Vercel or
  Cloudflare site: allow your IP in the firewall first, or scan a preview URL."
- (b) Allow Penthera's user agent in penthera.org's firewall. That makes the
  demo smooth but teaches the wrong habit.

**D4. The hook depends on the npx cache path.**
- (a) **Recommended:** when the baked-in path is missing, fall back to
  `npx -y penthera@<installed version> hook run` (pinned, so no silent upgrade),
  and keep exiting 0 only if that fails too.
- (b) Block the commit when Penthera can't be found (safe, but annoying when
  offline).
- (c) Keep it, and print the warning in red.

**D5. Broken compare links.**
- (a) **Recommended:** merge #89, which adds `docs/compare/cloudflare-security-audit.md`.
- (b) Remove the three links from `site/compare.json` until it lands.
